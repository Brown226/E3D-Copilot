# 后期功能优化改进计划

> 📅 **定位**：在现有 v2.0 基础能力之上，补齐与 DeepSeek-Reasonix 对比中暴露的工程成熟度短板，并引入真·子代理（多 Agent）。
> 🎯 **来源**：`arch/对比分析-E小智vsReasonix.md`（第十三~十六节）
> ⚠️ **硬约束**（贯穿所有改动）：**.NET Framework 4.8 / C# 7.3**（E3D 宿主锁定 32 位加载器）、所有 E3D API 调用经 `ThreadMarshaller.InvokeOnUIThread`、内网/离线优先（默认本地 vLLM）。
> 🚫 **红线**：不得引入要求 .NET 8+ 的 NuGet 包（Microsoft Agent Framework / AutoGen.NET 均不兼容，详见对比文档 15.1）。

## 六、B3 详细实施计划：从 todo_write 到真·子代理（MVP）

> 代码事实核实：`AgentLoop` 为普通类可多实例（`AgentLoop.cs:59`）；`CopilotSession` 为普通类可独立 new（`CopilotSession.cs:10`）；`ToolExecutor` 为共享注册表（`ToolExecutor.cs:18`）；事件源 `Events/CopilotEvent.cs`。

### 6.1 MVP 范围
**只做"只读子代理并行派发"**。不做写类子代理、双模型、handoff（留 C2）。

### 6.2 现状 → 目标
| 项 | 现状 | MVP 目标 |
|---|---|---|
| 子代理执行器 | 无（`task` 仅前端类型）| 新增 `SubagentDispatchHandler`（`IToolHandler`）|
| 上下文 | 单 session 串行 | 每个子代理用独立 `CopilotSession` |
| 并行 | `todo_write` 记录后主 Agent 自己串行干 | 主 Agent `Task.WhenAll` 派多个只读子代理 |
| 前端区分 | 不区分来源 | 事件带 `AgentName`，前端按员工分组 |

### 6.3 改动清单
1. **新建 `Agents/SubagentContext.cs`**：`SubagentContext{ Name, SystemPrompt, IsReadOnly=true, Session=new CopilotSession() }` + `AgentResult{ Output, Evidence, Success }`。
2. **`ToolExecutor.cs` 加 `FilterReadOnly()`**：返回仅含 `IsReadOnly==true` handler 的浅副本（子代理工具集收紧）。
3. **新建 `Agents/SubagentRunner.cs`**：复用现有 `AgentLoop` 作为"员工"，共享 `ToolExecutor`（按只读过滤）；`TaggedSink` 包装 `_sink` 写入 `AgentName`。
4. **新建 `Handlers/SubagentDispatchHandler.cs`**：工具名 `dispatch_subagent`，参数 `name`/`system_prompt`/`task`/`mode`(=readonly)；`IsReadOnly=true`；调用 `SubagentRunner.RunAsync` 回传结果。
5. **`Events/CopilotEvent.cs` 加 `AgentName`** 字段（默认 null = 主 Agent）+ `WithAgent` 工厂重载。
6. **`CopilotController.CreateDefault`（`CopilotController.cs:224`）**：构造并注入 `SubagentRunner` + 注册 `SubagentDispatchHandler`。
7. **`SystemPrompt.cs`** 增补：允许主 Agent 用 `dispatch_subagent` 并行派发只读子代理。
8. **前端（最低成本）**：事件含 `AgentName` 时在 `tool:dispatch`/`tool:result` 显示 `[子代理: name]` 前缀（参考 `shared/ExtensionMessage.ts:334` 的 `SubagentStatusItem`）。

### 6.4 防护（复用现有机制）
| 风险 | 防护 |
|---|---|
| 子代理无限递归派子代理 | `MaxSubagentDepth=2`；子代理侧禁用 `dispatch_subagent` |
| 死循环 | 复用 `AgentLoop` 的 `MaxSteps` + Storm Breaker |
| 跨线程 E3D 调用 | 子代理 `ExecuteAsync` 已走 `ThreadMarshaller` |
| 上下文溢出 | 子代理独立 `CopilotSession` 走已有 `MaybeCompactAsync` |

## 七、不建议跟进项（避免无效投入）

| 项 | 原因 |
|---|---|
| 引入 MAF / AutoGen NuGet 包 | net48 不兼容，编译失败；升级 .NET 破坏 E3D 宿主 |
| OS 级沙箱（Seatbelt/bubblewrap/AppContainer）| E3D 数据库天然隔离；32 位宿主集成收益低、风险高 |
| 跨平台 / 多架构分发 | 仅 Windows x86 E3D 宿主 |
| 独立 CLI TUI | 无独立 CLI 形态，宿主是 E3D |
| Memory V5 完整执行编译器 | 过于复杂，简化分类器即可 |
| A2A 跨进程协议 | 进程内单宿主，无跨进程需求 |
| 完整 MAF Workflow 图引擎 | 过度工程，手写编排足够 |
