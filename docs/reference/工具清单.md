## 一、总览

主项目当前注册 **31 个常驻工具**，另有 **1 个条件注册工具**（`mcp_knowledge`，仅当配置 MCP 知识源时由 ToolRouter 注入），合计最多 **32 个**。

注册入口：
- `ToolExecutor.CreateDefault(...)` 注册 28 个（`DispatcherBackedHandler` × 7 + 含逻辑 Handler × 21）。
- `CopilotController` 在构造完成后注入 `run_skill`、`memory`、`dispatch_subagent`（共 3 个，依赖 SkillManager / MemoryManager / SubagentRunner）。
- `ToolRouter` 在检测到 MCP 配置时注入 `mcp_knowledge`（条件注册）。

注册分四类：

| 类别 | 数量 | 说明 |
|------|------|------|
| 透传型 E3D 工具（DispatcherBackedHandler） | 7 | 零业务逻辑，直接转发到 `IToolDispatcher` → `E3DToolDispatcher` |
| 有实质逻辑的 E3D 工具 | 14 | 内含业务编排、C# 直读、出图、计算等 |
| 元能力 / 文件工具 | 10 | 不依赖 E3D，提供文件、搜索、记忆、子代理等通用能力 |
| 知识与技能工具 | 2（+1 条件） | 技能包调用 `run_skill`、子代理派发 `dispatch_subagent`，以及条件注册的 MCP 知识检索 `mcp_knowledge` |

## 二、透传型 E3D 工具（7 个）

由 `DispatcherBackedHandler` 包装，路由到 `E3DToolDispatcher`（`src/E3DCopilot.Tools/Bridge/E3DToolDispatcher.cs`）的具体 `HandleXxx` 方法，Handler 本身不含业务逻辑。

| # | 工具名 | 只读 | 子操作 / 参数 | 说明 |
|---|--------|------|---------------|------|
| 1 | `query` | ✅ | `type` / `name` / `scope` / `limit` | 按类型（PIPE/EQUI/STRU/BRAN/ZONE/PROJ）、名称（支持 `*` 通配）、范围查询元素列表。scope 为递归搜索起点 |
| 2 | `modify` | ❌ | `dburi` / `attributes` / `preview` / 兼容 `element`+`attribute`+`value` | 修改元素属性，支持单属性与批量；`preview=true` 仅预览 |
| 3 | `check` | ✅ | `type`（exists / attribute / attribute_complete / naming / name_consistency / clearance / distance / bore_consistency / change_status / room_number） | 校验与检查：存在性、属性完整性、命名规范、间隙、口径一致性、房间号等 |
| 4 | `export` | ❌ | `action`（export / generate_pml）× `format`（csv / excel / pml）× `filePath` | 导出元素列表到 Excel/CSV，或生成 PML 脚本 |
| 5 | `design` | ❌ | `action`（create_equipment / create_component / delete_element / set_position） | 创建/修改设备与结构元素、设置坐标 |
| 6 | `piping` | ❌ | `action`（create_pipe / create_branch / add_fitment / set_spec） | 创建管道/分支、添加管件（FLANGE/VALVE 等）、设置规格 |
| 7 | `geometry` | ✅ | `action`（get_position / get_orientation / bounding_box / distance_between） | 空间几何查询：位置、朝向、包围盒、间距 |

## 六、路由与调度关系

```
LLM 调用工具
   │
   ▼
ToolExecutor（32 个 Handler 注册表）
   │
   ├─ 7 个 DispatcherBackedHandler ──► IToolDispatcher 接口
   │                                     │
   │                                     ▼
   │                              E3DToolDispatcher（E3DToolDispatcher.cs）
   │                                     │  HandleQuery / HandleModify / HandleCheck /
   │                                     │  HandleExport / HandleDesign / HandlePiping /
   │                                     │  HandleGeometry / HandleExecutePml / HandleCalculate
   │                                     ▼
   │                              IE3DEnvironment（RealE3DEnvironment / SimulatedE3DEnvironment）
   │                                     ▼
   │                              E3D API / PML（Command.CreateCommand(str).RunInPdms()）
   │
   ├─ 13 个含逻辑 Handler ──► 直接调用 dispatcher（C# 直读、出图、计算等）
   │
   └─ 12 个元能力/知识 Handler ──► 文件 / 记忆 / 子代理 / MCP（不依赖 E3D）
```

要点：
- `ToolExecutor` 是唯一的工具注册表；`ToolRouter` 负责把工具名再分发到具体 Handler（含 MCP 可选路由器）。
- 透传型工具（`query`/`modify`/`check`/`export`/`design`/`piping`/`geometry`）与 `execute_pml`/`calculate` 共享同一条 `E3DToolDispatcher` 链路；`modify` 等写入操作的审批由 `PermissionGate` 把关（只读自动执行、写入需确认、批量 >5 先展示计划）。
- `get_attributes` 走 `IE3DEnvironment.GetAttribute`（C# API 直读），不经 PML，性能更优。
- `generate_iso_drawing` / `query_material` / `get_pipe_info` / `autocad` 等 ISO 出图与 CAD 工具在 `ToolRouter` 中直接透传到对应 Handler，不经 `E3DToolDispatcher` 的子操作路由。
